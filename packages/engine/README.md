# `@monospace-timetable/engine`

The timetable engine and `.xlsx` writer from [Monospace](https://github.com/camwooloo),
extracted so it runs in **Node and in a browser from one source**.

It takes a plain JSON "school document" — years, closures, the day, room lists,
templates, week changes, bookings and options — and writes the formatted
workbook Monospace produces. No server, no database, no network.

Licensed **AGPL-3.0-only**. Cam Wooloo owns the copyright outright.

---

## What it is for

A school with no budget should still get the timetable workbook. This package is
the part that does the work; the desktop shell (`wry` + `tao`) and the
single-file `.html` are hosts around it.

```ts
import {
  readSchoolDocument,
  buildTimetableModel,
  bufferTimetableWorkbook,
} from "@monospace-timetable/engine";

const read = readSchoolDocument(JSON.parse(await file.text()));
if (!read.ok) throw new Error(read.issue.message);

const built = buildTimetableModel({
  document: read.document,
  password: "staffroom",   // optional; never stored
  generatedBy: "A Okafor",
});
if (!built.ok) throw new Error(built.error);

const bytes = await bufferTimetableWorkbook(built.model);   // Uint8Array
```

`streamTimetableWorkbook(model)` returns a Web `ReadableStream` instead, for a
host that wants to pipe rather than buffer. **Both are the same writer.**

---

## ⭐ The one writer

The exceljs **streaming** `WorkbookWriter` is the only writer in this package,
on every target. The buffered `ExcelJS.Workbook` is not imported, referenced or
reachable — it silently ignores `useSharedStrings: false` and differs from the
streaming writer in 47 of 50 zip parts. `test/source.test.ts` asserts it never
comes back.

## What the fixture gate proves

`npm run gate` regenerates the workbook and compares it to bytes **generated by
Monospace's own writer**, member by member, on the raw compressed data.

> ⚠️ **The gate is `npm run gate`, not `npm test`.** It is a plain Node program
> — `gate/run.ts` — that prints its report and exits non-zero, with no runner,
> no reporter and no IPC. `worksheet.protect()` runs 100,000 SHA-512 rounds
> *synchronously*, once per sheet, 40 sheets to a workbook and six workbooks to
> a run; nothing yields for tens of seconds. Under vitest that starved the
> reporter RPC, and a run in which **every test passed** still exited 1 with
> `[vitest-worker]: Timeout calling "onTaskUpdate"` — on CI only, because the
> runner is slower. `npm test` keeps the light unit tests and takes ~14 s.
> Both run in CI, in that order, and both are asserted to still exist first.

| case | zip members | identical raw | identical after normalising | file size |
|---|---|---|---|---|
| every option on, with a password | 50 | 9 | 41 | ~256,190 |
| every option off | 50 | 49 | 1 | 169,049 — **exact, every run** |
| **browser bundle**, sandboxed in a `vm` | 50 | 9 | 41 | ~256,190 |

⚠️ **The protected file's total size moves by a few bytes between runs, and
that is expected rather than sloppy.** The random salt is different every time
and deflates differently, so the 40 sheet parts that carry one differ in length.
That is exactly why the gate compares *members*, with the volatile fields
normalised, rather than hashing the whole file — a whole-file hash could never
pass, and a whole-file *size* check would be a coin toss. The unprotected file
has no salt in it and is byte-for-byte identical, every run.

Exactly **three** things are normalised, and each still has to *match* — the
substitution counts are compared too, so a file that stopped writing a
`saltValue` cannot pass as "normalised":

| normalised | why it cannot be deterministic |
|---|---|
| `saltValue` | 16 random bytes per sheet per run. A fixed salt would make every Monospace workbook in the world share one. 40 per run here. |
| `hashValue` | SHA-512 over the password and that salt. 40 per run. |
| `dcterms:modified` | exceljs sets it from the wall clock at `WorkbookWriter` construction, before the writer re-points `created`. 1 per run. `dcterms:created` **is** compared. |

**Anything else is a regression, including a compression-level change** — which
is why the comparison is on raw compressed bytes and not on unzipped XML.

The gate also asserts the `CT_Worksheet` element sequence across **84 sheet
parts, 0 violations** — and proves that check works by disabling the
`sheetProtection` hoist, which reports **exactly 40 violations** (2 cycle-week
templates + 38 teaching weeks; the half-term and info sheets are never
protected).

`fixtures/palette.txt` pins every class code to its hex, so a change to
`colourForClass()` is a diff somebody has to look at rather than a colour
quietly moving in every school's workbook.

### The twelve checks, in the order they run

| | check | ~time |
|---|---|---|
| 1 | `fixtures/palette.txt` — every class code → its hex, and the `-` rows that must get **no** fill | 2 ms |
| 2 | our bytes vs `reference-full.xlsx` — every option on, with a password | 3.8 s |
| 3 | our bytes vs `reference-plain.xlsx` — every option off | 1.7 s |
| 4 | `CT_Worksheet` element sequence, 84 sheet parts | 17 ms |
| 5 | the hoist **enabled** — `<sheetProtection>` immediately after `</sheetData>`, exactly one, on 40 sheets | 14 ms |
| 6 | the hoist **disabled** — the sequence check must report exactly 40, all `sheetProtection` after `conditionalFormatting` | 3.8 s |
| 7 | the committed fixtures vs Monospace's writer **today** — ⚠️ reported **SKIPPED**, by name, without a checkout | 5.6 s |
| 8 | the browser bundle builds, unminified and minified | 71 ms |
| 9 | the unminified bundle, executed in a `vm` with only browser globals, vs Monospace's reference | 32 s |
| 10 | the **minified** bundle — the form that ships — same comparison | 32 s |
| 11 | exactly one `readable-stream` in the bundle | 0 ms |
| 12 | the published `dist/`, imported by Node, writes a workbook — ⚠️ **fails** rather than skips on CI | 3.9 s |

Steps 2–6 share **one** generation of each workbook; steps 7, 9, 10 and 12
generate their own, because an independent run is the whole point of each.
A green run prints every number above; a red one names the zip member, the
character offset and quotes both sides.

## ⭐ The file format

`SchoolDocument` (`src/model/document.ts`) is what a school saves, so it is a
**format** — it will be in mail attachments and on shared drives, and it will be
hard to change. `fixtures/school.fixture.json` is a worked example, checked by
being the exact input the reference workbooks are built from.

**How an older file is read:**

1. **A file from the future is refused, not best-efforted.** Reading what we
   understand and dropping the rest produces a workbook that looks complete and
   is wrong. A school that cannot open a file updates the app; a school handed a
   quietly incomplete timetable teaches from it.
2. **An older file is migrated one version at a time.** `MIGRATIONS[n]` takes
   version `n` to `n+1`, purely, never in place. A shipped migration is never
   edited — it describes files that already exist.
3. **Adding an optional field with a compatible default needs no version bump.**
   That is the main mechanism and should stay the common case.
4. **Unknown keys are reported, not dropped**, so a host can warn before saving.

Validation is of **shape, not sanity**: a year whose anchor is not a Monday
opens, and the engine complains downstream where there is a workbook to print
it on. Refusing to open a file for a fixable data problem strands the only copy
of it.

Deliberately **not** in the format: resolved weeks (derived by `buildYear()` on
every open), the export password, and per-class colours.

## Portability: the four changes to the writer

`src/workbook/timetableWorkbook.ts` is Monospace's file, and these are the whole
diff. `test/provenance.test.ts` holds each one in force; the fixture gate proves
nothing else moved.

1. **`import "server-only"` is gone.** A Next.js tripwire that throws in any
   client bundle — and the client bundle is the only target that matters here.
2. **`node:stream` became `./stream`**, which the *package* resolves to a Node
   or a browser implementation.
3. **exceljs is imported as the streaming writer directly**, not through the
   barrel. exceljs's `"browser"` field points at a dist bundle with **no
   `stream` namespace at all**, and the barrel drags in the reader → unzipper →
   bluebird, which crashes on `process.versions`. The `ExcelJS` name survives as
   `import type` only, which is erased and reaches no bundle.
4. **`bufferTimetableWorkbook()`** beside the streaming entry point. Same
   writer, a collector on the end.

`src/lib/` is Monospace's pure spec, and **six of its nine files are
byte-identical**; the other three differ only in an import path that had
nowhere to point. `test/provenance.test.ts` pins that, because the comments in
those files are the specification.

## Two targets, one package

The Node/browser split is a property of **`package.json`**, not of a bundler
config — two configs is two chances to diverge, and the divergence is a runtime
failure on only one target.

```jsonc
"exports": { "./stream": { "browser": "…/stream.browser.js", "default": "…/stream.js" } },
"browser": { "./dist/workbook/stream.js": "./dist/workbook/stream.browser.js" }
```

Both forms are present because bundlers honour different ones.

### Browser shims

`BROWSER_SHIMS` in `src/browser/shims.ts` is the list, **as data**, so both
bundles read it rather than restating it. `scripts/build-browser.ts` is the
esbuild worked example. Every entry was found by building and reading the
resolver's complaint:

| | | why |
|---|---|---|
| alias | `stream` → `readable-stream` | `archiver-utils` does `require('stream').Stream` while exceljs does `require('readable-stream')`. |
| alias | `readable-stream` → itself | **⭐ The dedupe, and the one that bit.** npm nests a dozen copies (v4 root, v3.6.2 under seven packages, v2.3.8 under four). Each is a distinct `Stream` class; archiver's `instanceof` check fails inside the **first** `addWorksheet()` with a message that mentions nothing about it. Aliasing the bare specifier converges every nested copy — which is also why `readable-stream` is pinned to `^3.6.2`, the version exceljs and the zip stack were written against. |
| alias | `zlib` → `browserify-zlib` | `crc32-stream` deflates every member with `new DeflateRaw`. |
| alias | `crypto` → local shim | exceljs's `encryptor.js` runs **100,000 sequential SHA-512 rounds synchronously**, so WebCrypto cannot back it. `create-hash` + `randombytes`, not `crypto-browserify`. |
| alias | `events`, `util`, `path` | `readable-stream` 3, `archiver-utils`, `compress-commons`. |
| alias | `fs` → empty | Required by exceljs and never called; only the `{ filename }` constructor uses it. |
| inject | `process` | `nextTick` must be a **microtask** or stream events reorder against promises. |
| inject | `Buffer` | ⚠️ Used as a **global**, so nothing imports it and nothing reveals the dependency until it runs. Injected via a one-line ESM re-export, because a bundler injecting the CJS `buffer` package sees only a `default` and leaves the identifier unbound — building clean and throwing at runtime. |
| inject | `setImmediate` | Must stay a **macrotask** (`MessageChannel`), or a long export freezes the window instead of yielding to paint. |
| define | `global` → `globalThis` | `randombytes`' browser build reads `global.crypto`. ⚠️ Only reached when a password is used, so its absence breaks precisely the workbook that was meant to be locked. |

`DEAD_SUBGRAPH` cuts archiver's filesystem plugins (`glob`, `graceful-fs`,
`lazystream`, `tar-stream`, …), which a writer that only pipes into a stream
cannot reach. That is what removes `assert` and `constants` from the graph
entirely — it is why the shim list is as short as it is, not a size tweak.

**The browser build is executed, not just compiled.** `gate/browser.ts` bundles
it and runs it in a `vm` context that has **only browser globals** — `process`,
`Buffer`, `setImmediate`, `require` and `module` are absent — then compares the
bytes it produces against Monospace's reference through the same `compare()`
every other check uses. Both the unminified bundle and the **minified** one,
because minified is the form inside `timetable.html` and the `.exe`.

## Scripts

```bash
npm run gate           # ⭐ THE GATE — our bytes against Monospace's. ~85 s.
                       #    No Monospace checkout required; it says so and
                       #    reports the live comparison as SKIPPED without one.
npm test               # the light unit tests. ~14 s.
npm run typecheck
npm run build          # tsc → dist/, then fix ESM specifiers
npm run build:browser  # esbuild → build/browser-bundle.js
npm run fixtures:refresh   # ⚠️ needs a Monospace checkout
```

Run `npm run build` before `npm run gate` to have the published-`dist/` check
run rather than skip; CI does, and the gate **fails** there if it has not.
From the repository root, `npm run check` is typecheck + tests + gate.

`fixtures:refresh` regenerates the committed reference workbooks **using
Monospace's own writer** and is deliberately not wired into `test` or `build` —
a fixture that regenerates itself before every comparison compares a file to
itself and passes forever. Point `MONOSPACE_SOURCE` at the checkout if it is not
the sibling directory.

The reference writer is loaded **unmodified** from that read-only checkout. The
only thing resolved for it is `server-only`, intercepted by
`scripts/register-hooks.mjs` and answered with an empty stub — see
`test/stubs/server-only.cjs`. Copying the file and deleting that line would make
the gate compare our writer against our own edit of theirs. Both entry points
that reach it (`npm run gate`, `npm run fixtures:refresh`) register those hooks;
a new one that does not will fail with Next.js's tripwire in the stack.

## Traps carried over from Monospace

These bit somebody already. The full arguments are in the files' own banners.

- **`years[0]` is always wrong** — it is the school's *oldest* year.
  `pickAcademicYear()` is the one rule, and Monospace records five separate
  readers having had this bug. The fixture keeps an old year first on purpose.
- **The screen IS the export.** `gridClassFill()` returns the printed byte in
  every theme. Any change must be proved by generating the workbook and diffing
  it; three claims about this palette have failed measurement. **Measure, never
  reason from the constants.**
- **The tab is authoritative, not cell B1.** All 38 week sheets in the reference
  workbook disagree with themselves; `weekBandLabel()` writes the sheet's own
  cycle label. Replicating a bug faithfully is not fidelity.
- **A cleared week change must not be linked.** A linked empty cell resurrects
  the very lesson somebody moved off it, the moment Excel recalculates.
- **A template sheet is the *standing* week.** Building it from a particular
  week carries that week's closures into it — and under linking, two whole days
  evaluate to `""` across half the workbook. `daysAlign()` cannot catch it: the
  row shape matches, the content was week-specific.
- **A booking's status is `pending | approved | rejected | cancelled`**, and
  only the first two put anything in a cell. Any other string is a booking that
  silently does not exist.
